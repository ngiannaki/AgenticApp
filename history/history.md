- **Change:** Added deterministic answer citations to the chat, plus a Documents-page raw chunk browser (with tags) for inspection/preview

- **Details:** Two features, one shared new MCP tool:
  1. **Citations**: every `retrieve_document_v2` tool result's `grounding` blocks (already carrying document_id/chunk_id/page/section) are collected server-side across a whole chat turn, deduped by `chunk_id` in first-appearance order, and sent as a new `citations` SSE event (`events.citations`, persisted as a `citations`-type step in `routers/chat.py`) right before the final `message` event — deliberately not self-reported by the model, so the citation list can't be hallucinated. `DEFAULT_SYSTEM_PROMPT` (backend/apps/client/config.py) now asks the model to drop matching `[1]`/`[2]` markers in its prose, numbered in that same first-appearance order. Exposed via a new REST endpoint `GET /api/documents/{id}/chunks` (routers/files.py, ownership-checked like the existing content endpoint), consumed by a new "Preview chunks" action (layers icon) on the Documents page that expands an inline panel listing every chunk with its tags (chunk_id, chunk_index, page/sheet/row, chunk_content_type, section) and text.

## 2026-09-24

- **Details:** The first version of these skills documented *what the tools are*; this version documents *how to think* — each now follows one shape: when to use → numbered procedure with explicit checkpoints → decision tables → self-check checklist → retry budget and stop condition → anti-patterns table → worked example. Written deliberately as concrete imperative checklists rather than prose, because the chat model is `gpt-oss:20b` (DEV) / `gpt-4o-mini` (PROD), not a frontier model, and subtle guidance doesn't survive that. Every limit quoted in them is read from real config rather than invented (query caps from `DbMcpSettings`, sandbox timeout/output/artifact caps from `CodeMcpSettings`, `max_top_k`/`max_tool_result_chars` from `LangchainRagSettings`/`ApiSettings`).
  - **Citation filtering (code change)**: `_collect_citations` folds *every* chunk from *every* `retrieve_document_v2` call into the Sources strip, which is what makes the list impossible to hallucinate — but combined with the new "retry retrieval with a wider top_k" procedure it would have produced a strip with dozens of chunks the answer never used. Added `_cited_only(citations, answer)` in streaming_agent.py: parses `[n]` markers out of the final answer and keeps only those citations, applied on both the normal and forced-final-answer paths. Deliberately does **not** renumber or rewrite the answer text — the frontend labels each chip from the citation's own `number`, so filtering alone keeps chips aligned with the prose (gaps like `[2]`, `[5]` are correct), and rewriting answer text risked corrupting list indexing inside a code block (`arr[1]`). Falls back to the unfiltered list when the answer contains no markers at all, so a model that ignores the numbering instruction still shows sources rather than none. Verified against four cases: normal filtering, no-markers fallback, model-invented dangling marker, and code-like `arr[0]` text.
  - **rag-retrieval-strategy**: now a 7-step loop — decompose the question into discrete facts, scope via TOC, retrieve, classify each fact's evidence as DIRECT/PARTIAL/ABSENT (with "could you quote it?" as the test), retry changing exactly one variable in priority order (reword using the document's own vocabulary → relax filters → raise top_k 5→12→25 → re-scope), stop after 3 attempts per fact and report the gap honestly rather than filling it from general knowledge. States explicitly that retrieval is deterministic, so re-running an identical call is wasted iteration, and warns that `top_k=25` with neighbor expansion can blow the 8000-char tool-result cap.
  - **code-execution-and-artifacts**: adds the sandbox's real constraints (no network/secrets/DB access, no pip install since the shell tool is off, 10s default / 60s max timeout, 200KB output cap, 5 artifacts × 10MB) and a verify-the-result-not-the-exit-code step — `success: true` only means exit 0, so the procedure requires checking stdout against a success criterion stated *before* running, plus `truncated`/`timed_out`/artifact presence. Includes the cross-tool pattern for charting DB data (query with `db_query_data` first, embed rows as a literal, since the sandbox can't reach Postgres) and a 3-attempt failure budget.
  - **sql-database-safety**: adds the preview-before-mutate step (run the same filter as a `SELECT count(*)` and tell the user the real number before updating/deleting), and documents that `allow_full_table_delete` and `allow_destructive_schema_ops` are **server master switches disabled by default** — so those calls are rejected regardless of call flags, and the correct response is to say so, not to retry with different flags or simulate the operation via a `WHERE 1=1` filter.
  - **citations-and-grounding**: rewritten around the new filtering behavior — markers are now the filter deciding what the user sees, not decoration; documents why numbering gaps are correct, and what each failure mode looks like to the user.
  - **document-ingestion**: adds an ordered diagnostic (`get_document_info_v2` chunk count → `get_table_of_contents_v2` → interpret by file type) so an ingestion failure isn't misreported as a content fact, plus the pptx-has-no-table-tagging trap.

- **Change:** Found and fixed a real citation-mismatch bug in production use — replaced the `[n]` bracket-number citation mechanism with a `<citation id="..."/>` tag the model copies verbatim from the chunk it's citing, instead of computing a running position itself
- **Files:** backend/apps/api/streaming_agent.py, backend/apps/client/config.py, backend/skills/citations-and-grounding/SKILL.md, backend/skills/rag-retrieval-strategy/SKILL.md

  - **Root-caused by querying the live Chroma collection directly** (`chromadb.HttpClient(host='localhost', port=8010)`, collection `docv2_d158a910-...`): the document has two tables that could plausibly be "the income statement" — the real one on page 51 (`h1` correctly captured as "...Consolidated Statements of Income...", matching the TOC) and an unrelated MD&A percentage-of-revenue table on page 40 (`h1: None`, `chunk_index=303`) — "Revenue 100.0%, Cost of revenue 28.9%..." — returned by an earlier, broader retrieval call in the same turn.
